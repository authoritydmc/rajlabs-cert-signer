AIR-GAPPED ZERO-TRUST ARCHITECTURE

Enterprise Certificate Signer

Containerized enterprise PKI certificate authority with RFC 8555 ACME automated issuance, CRL distribution, and client trust management.

🛡️ Zero-Trust Security Model

The root private key is strictly isolated. The Docker engine only holds intermediate keys (e.g., int-server, int-wifi, int-iot) and the public root certificate as a trust anchor.

💡 Core Use Cases

1. Automated Ingress & Reverse Proxies

Native ACME support allows Traefik, Caddy, NGINX Ingress, and Certbot to automatically request, obtain, and auto-renew TLS certificates for internal services with zero human intervention.

2. Microservice & mTLS Infrastructure

Use the authenticated REST API (/api/v1/sign) to issue short-lived certificates dynamically for service-to-service communication, gRPC, and internal databases.

3. WiFi 802.1X & Enterprise IoT

Isolated intermediates (int-wifi, int-iot) allow scoping certificate authorities by hardware domain, preventing cross-domain compromise.

4. Centralized Revocation (CRL)

Immediate revocation via API updates the certificate database and regenerates the standard X.509 CRL at /crl/*.crl for real-time validation.

💻 1-Command Client Trust Installation

End certificates do not require manual bundle chaining when client devices have the Root and Intermediate CAs installed in their OS trust stores:

🪟 Windows (PowerShell as Administrator) LocalMachine\Root + CA

irm http://<ca-server-host>:8080/install-trust-windows.ps1 | iex

🐧 Linux (Ubuntu, Debian, RHEL, CentOS, Rocky, Alpine) System CA Store

curl -fsSL http://<ca-server-host>:8080/install-trust-linux.sh | sudo bash

🚀 Deployment Guide

  1. Mount Intermediate CA: 
    .\import-intermediate.ps1 -TargetIntermediate "int-server"
  2. Start Docker Services: 
    docker compose up -d --build
  3. Configure ACME in Certbot / Traefik: 
    certbot certonly --standalone --server http://<ca-server-host>:9000/acme/directory -d myservice.Enterprise.local
