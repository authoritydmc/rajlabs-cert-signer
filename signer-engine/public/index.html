Tutorial: How to Generate an Intermediate CA Signer

Follow these guided steps to generate signers using the offline Root CA without risking root private key exposure.

1 Option A: Use Automated Helper Script (Recommended)

Run on your secure machine. It handles OpenSSL extensions and segregates files automatically:

# Windows PowerShell:
.\scripts\generate-offline-ca.ps1 -OrgName "MyCompany" -IntermediateName "int-server"

# Linux / macOS:
./scripts/generate-offline-ca.sh "MyCompany" "US" "California" "San Francisco" "int-server"
2 Option B: Manual OpenSSL Commands
# 1. Generate Intermediate Private Key & CSR
openssl genrsa -out int-server.key.pem 4096
openssl req -new -sha256 -key int-server.key.pem -out int-server.csr.pem \
  -subj "/C=US/ST=California/L=San Francisco/O=MyCompany/CN=MyCompany Intermediate CA"

# 2. Create extension file: ext.cnf
echo "basicConstraints = critical, CA:true, pathlen:0" > ext.cnf
echo "keyUsage = critical, digitalSignature, cRLSign, keyCertSign" >> ext.cnf

# 3. Sign CSR with Offline Root CA
openssl x509 -req -in int-server.csr.pem -CA root-ca.cert.pem -CAkey root-ca.key.pem \
  -CAcreateserial -out int-server.cert.pem -days 3650 -sha256 -extfile ext.cnf
3 Import Into Web UI

Go to Intermediate CAs → + Import Intermediate CA. Paste the contents of root-ca.cert.pem, int-server.cert.pem, and int-server.key.pem. Your key is stored safely using AES-256 encryption.

Tutorial: Certificate Revocation & CRL Distribution

Learn how revocation works and how client devices query Certificate Revocation Lists (CRL).

1 Revoking a Certificate via API

Submit a revocation request using your API token and the certificate's serial number:

curl -X POST http://:9000/api/v1/revoke \
  -H "Content-Type: application/json" \
  -H "x-api-key: cert_3a9f..." \
  -d '{
    "serial": "1002",
    "reason": "keyCompromise"
  }'
2 Automated CRL Generation

When a revocation occurs, the engine automatically runs openssl ca -gencrl and regenerates the CRL file.

3 Public CRL Query Endpoint

Firewalls, web servers, and client systems can query real-time CRLs with proper application/pkix-crl headers: 

http://:9000/crl/int-server.crl
